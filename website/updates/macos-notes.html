Plantoir 1.9.3

Plantoir 1.9.3 is for the Mac and Windows. On the Mac it is two fixes to class sites. Windows moves from 1.9.0 to 1.9.3 and gets what the Mac got in 1.9.1 and 1.9.2 as well. The Mac download came out on 10 November 2026 and the Windows download on 12 November.

Before you update

  • The two fixes to class sites are in the sites themselves. After updating, deploy again each section that has a GeoGebra sketch written as typed commands, or a text block that wraps. A site already online keeps the fault until you do.
  • A deploy you scheduled before updating keeps the fault until you open its folder in Plantoir 1.9.3 once.

Fixed

  • A GeoGebra sketch written as typed commands showed as a black box on a class site and could not be dragged. This had been so since 1.9.0. It now draws and responds.
  • The copy button on a text block that wraps could not be pressed, so nothing was copied. It now works. Blocks that do not wrap were never affected.

Plantoir 1.9.2

Plantoir 1.9.2 is one fix for the Mac: after an update, a deploy builds the site again first, so the update's changes to class sites reach sites already online. Windows stayed at 1.9.0; its next release was 1.9.3.

Before you update

  • A deploy you scheduled before updating still sends the site as the earlier version built it, until you open its folder in Plantoir 1.9.2 once.

Fixed

  • With 1.9.1, deploying a section whose pages had not changed could send the site as the earlier version had built it. 1.9.1's changes to task boxes and to printed quiz blanks then never appeared. The first deploy of each section after an update now builds the site again, even when no page changed. That deploy takes a little longer, and there is nothing you need to do.

Plantoir 1.9.1

Plantoir 1.9.1 is for the Mac. It stops previews being reachable from other computers, adds a Problems tab to each section, and makes Cloudflare Pages the destination for new courses. Windows received these changes in 1.9.3.

Before you update

  • Security: previews. Until this version, a running preview could also be opened from other computers on the same network as your Mac, a school's Wi-Fi for example. A preview now opens only on the Mac that is running Plantoir, so it can no longer be opened from another device, such as a tablet on the same Wi-Fi. Each working folder's website builder is set up again once after updating.
  • Security: the website builder. It takes October 2026's security updates. They cover the part that deploys to Cloudflare, and the system libraries that make the secure connection for every deploy. The first preview after updating takes longer while the builder is rebuilt, once.
  • The first deploy after updating may ask "Deploy classes dated later?" with every class ticked. The tick has changed its meaning: a ticked class is now deployed, where before it was hidden. Untick any class you want kept hidden.
  • The two changes to class sites below, to task boxes and to printed quiz blanks, reach a site already online when you preview its section and then deploy it. In 1.9.1 a deploy on its own does not always bring them; 1.9.2 corrects that.

New

  • A Problems tab on each section. A section now has two tabs, Website and Problems. The Problems tab lists every problem a preview or deploy found in one table: Kind, Page, Problem, First found, Last found, and the repair where there is one. A problem fixed in a page that sections share clears from every section. A section with problems shows a warning beside its name in the sidebar. An alert appears only when a build finds something new, and its Show button opens the tab. The tab replaces the list of folder problems that appeared after a build.
  • Fix with Claude… and Fix with Codex… Tick problems in the table and choose one of these buttons under it. Claude Code or Codex opens on the course with each ticked problem, its page, and the guidance for that kind of problem. A button appears only when that assistant is installed, and never on a reference course.

Changed

  • New courses deploy to Cloudflare Pages unless you choose otherwise. Cloudflare is listed first in the New Course window. Courses you already have keep deploying where they do now. Choosing Netlify shows a note: Netlify accounts made since September 2025 have a monthly allowance that every deploy of every section uses, and running out pauses every site on the account. If the Cloudflare Account ID is missing, Plantoir warns when you create the course, and Deploy stops with an Open Settings… button.
  • At Deploy, ticked means included. Deploy asks "Deploy classes dated later?" with every class ticked. A ticked class is deployed. An unticked class is hidden first, with a backup, and Section ▸ Undo Last Change brings it back. The preview then matches the deployed site. The button beside Cancel is Deploy Ticked, and Keep All is gone. Section ▸ Publish Pages… no longer asks about classes dated later.
  • Coming back to a section while it is deploying shows that deploy: its progress, its console and Cancel. Deploy is unavailable until it ends. A deploy that finished while you were away shows how it ended, once.
  • A token that Cloudflare refuses is explained in the window, with Cloudflare's reason and a hint about the permission it needs. A saved token is cleared only when the service refuses it, never because the service could not be reached.
  • The assistant stops after six tries at one request and says that nothing was changed.
  • Open in Obsidian says so when Obsidian did not open.
  • A diagram that cannot be drawn says why. It names a missing font, or \$, \textdollar or \textdegree when one of them is the cause. The diagram after it is no longer blamed.
  • Task boxes on class sites line up with the words beside them, on screen and on paper.
  • The guidance Claude Code and Codex follow for handouts and pages adds house rules for tables, decimals, borders, finite differences and task cards.
  • At the command line, ./deploy.sh with no destination deploys where the course's settings say.

Fixed

  • A blank in a quiz printed from a class site was invisible. It is drawn again, with about two lines of room for the answer.
  • Right after a deploy finished, the next deploy of the same section could be blocked for a moment.
  • In a folder that holds both shared pages and a section's own pages, a problem could name a shared page under the wrong folder, and the date of a linked shared page was not written back to its file. Both now use the shared file.
  • Every alert in the main window showed the "Don't ask again" checkbox that belongs to the offer of Obsidian's add-ons. Only that offer shows it now.

Plantoir 1.9.0

Plantoir 1.9.0 is for the Mac and Windows. It adds GeoGebra sketches and text blocks that wrap to class sites, and Open in Obsidian now opens the page you are previewing. The Mac download came out on 24 October 2026 and the Windows download on 31 October.

Before you update

  • Security: the website builder now runs on a version of its underlying software that still receives security fixes. The version it used stopped receiving them in April 2026. The newer version also stops trusting the two root certificates described in the 1.8.7 notes when a site is deployed to Cloudflare Pages. Your sites look the same. On the Mac, the first preview after updating takes a few minutes longer, once.

New

  • GeoGebra sketches. A geogebra block puts a working sketch on a page. Write it one of three ways: file: and the name of a .ggb file saved beside the page or in Media; GeoGebra commands, one a line; or material_id: and the ID of a public sketch on geogebra.org, which Plantoir copies when the site is built. Students see a picture of the sketch and tap "Open the sketch" to use it. The sketch is served by your class site, and students' browsers never visit geogebra.org. A sketch can sit in a self-check question or in its explanation. It cannot sit in a choice. To copy a geogebra.org sketch again after it changes there, change the block, for example by adding version: 2. The ready-made MPM2D course has a sketch in "Explorations/The Slope-Angle Conjecture".
  • Text blocks that wrap. Write text wrap after the three backticks that open a code block, and its long lines wrap at the window's width. Each continued row shows "…" where a line number would be. Other code blocks still scroll sideways, and printing is unchanged.
  • Open in Obsidian opens the page the preview is showing. A section's Open in Obsidian, in the toolbar, the Section menu and the section's own menu in the sidebar, opens the Markdown file behind the page you are previewing, hidden pages included. Course ▸ Open in Obsidian is unchanged.
  • Typing "open this in Obsidian" to the assistant does the same.

Changed

  • A quiz that the site reads differently from the way it was written is now reported as a folder problem.

Fixed

  • When Swift could not be made ready for runnable code, Plantoir always blamed the internet connection. It now gives the real reason: not enough room, a damaged download, no connection, or a download that could not be unpacked.

Plantoir 1.8.7

Plantoir 1.8.7 is for the Mac and Windows. It is mostly fixes, to class sites and to the app, with one security update on the Mac.

Before you update

  • Security: on 20 October 2026 the certificate authority eMudhra reported that some of its certificates were compromised. The website builder on the Mac still trusted the two root certificates above them, so someone holding one of the compromised certificates could in principle have posed as the service a deploy was connecting to. No such incident is known. After updating, deploys to Netlify no longer trust those two root certificates. Deploys to Cloudflare Pages were not fully covered until 1.9.0. The first preview after updating takes a little longer, once.
  • The fixes to class sites below reach a site already online when you preview its section and then deploy it.

New

  • Ask Claude Code or Codex, in a working folder, for a printed handout, and it offers a house style: the handout and its answer key from one source, with the school's header and footer in the corners. A starting handout and a starting quiz come with it.

Changed

  • In the plans for publishing and hiding, "Show the 16 pages already visible" is now a checkbox that adds those pages to the table above it. It was a triangle. After you choose Publish or Hide, the sheet shrinks to its answer, such as "Published 5 pages."
  • Links between pages on a site deployed to Netlify go straight to the page. A click used to pass through up to three redirects, each costing 80 to 250 milliseconds. Sites on Cloudflare, sites deployed to a folder, and Preview are unchanged.
  • A runnable code block that the site can show only as plain code, for example because a code block above it was never closed, is now reported as a folder problem that names the page and the line.
  • The font choice that read "Helvetica, Arial" is now labelled "System fonts (each device's own)", which is what it has always shown. Sites look the same.
  • The offer of Obsidian's add-ons for diagrams and graphs says again that Obsidian opens its settings in a window of its own after you click "Trust author and enable plugins".
  • A curriculum folder renamed without the word "curriculum", to "Expectations" for example, is still treated as curriculum. Its pages are not put into draft at the start of the year, not hidden with a class, and not listed as already visible.

Fixed

  • On a long printable page, Print could show its progress and never open the print window. This was seen in Safari on a page with 18 code blocks. The print window now opens. If the page cannot be prepared in 30 seconds, it says so and goes back to normal.
  • A page on a class site could jump down by several hundred pixels as its sidebar was drawn. The sidebar now scrolls only its own list.
  • A course made before 1.8.1 whose name contains a colon, such as "Physics: Mechanics", gets its website back at its next preview or deploy. Plantoir repairs the title on the course's front page and says so in the console. For a reference course, or a front page that is linked or locked, your file is left alone and only the website's copy is repaired. The hand fix described for 1.8.1 is no longer needed.

Plantoir 1.8.2

Plantoir 1.8.2 is for the Mac. It closes a privacy gap on class sites, adds a My Progress page for students, and draws Mermaid diagrams on Netlify sites again. Windows received these changes in 1.8.5.

Before you update

  • Privacy: preview and deploy each section again. Sites deployed to Cloudflare Pages or to a folder, and Preview, asked each visitor's browser to load a page-view counter from plausible.io on every page. A student's browser therefore contacted plausible.io, which shows it the browser's address and the page being read, as any such request does. Plantoir never set up an account with Plausible, so each page view was sent for a site address nobody had registered there. Whether Plausible kept any record of these page views has not been established. Sites deployed to Netlify with 1.2.0 or later did not load the counter. A site built with 1.8.2 no longer loads it; a site you do not deploy again keeps loading it.
  • Netlify sites with Mermaid diagrams: preview and deploy again to have the diagrams drawn.
  • If you once chose "Not Now" when Plantoir offered to add its guidance for Claude Code and Codex to your own CLAUDE.md or AGENTS.md, it offers once more, because the guidance has changed.

New

  • My Progress, a page for each student alone. A section gets a My Progress page when its pages have task boxes under a heading named "Test of success", "Tests of success" or "Success criteria". It counts the student's own ticks for each page, grouped by the class that first linked the page, with totals for each unit and overall. It comes right after the class folder in the sidebar and first in Key Links. The ticks stay in the student's browser and are sent nowhere. Course Settings has no switch for it.

Changed

  • A class site or preview built with 1.8.2 loads no page-view counter.

Fixed

  • Mermaid diagrams showed as the text they were written in on sites deployed to Netlify. The rule that keeps Netlify's badge off your pages was also blocking the diagrams.

Plantoir 1.8.1

Plantoir 1.8.1 is for the Mac. Students can tick the task boxes on your pages, and runnable programs can ask for input as they run. Windows received these changes in 1.8.5.

Before you update

  • Preview and deploy each section again to bring these changes to your sites. Until then a site works as it did.
  • Programs that ask for input as they run need Netlify or Cloudflare. On a site deployed to a folder, students type their input into the box before pressing Run, as in 1.8.0. So does a page that shows a frame, an embedded PDF, or a picture from another website; the page says why, and Plantoir names these pages when you preview and deploy.
  • A course you started empty whose name has a colon and a space (for example "Physics: Mechanics") may build no front page for a section. This release does not repair a section that already exists.   • The ready-made courses' pages that said checklists cannot be ticked were rewritten. A course you already created keeps its pages.

Fixed

  • A new course started empty, or a new section, whose course name has a colon and a space now gets a front page that builds.
  • A % in the file name of a curriculum expectation stopped the site from building.

Plantoir 1.8.0

Plantoir 1.8.0 is for the Mac. It adds Python and Swift programs students can run on the page, and self-check quizzes. Windows received these changes in 1.8.5, and runnable Swift in 1.8.6.

Before you update

  • The first preview after updating takes a few minutes longer, once, while Plantoir rebuilds its website builder.
  • Preview and deploy each section again. A site built before 1.8.0 keeps one fault until you do: a printable page opened by a link from a page in another folder, the home page for example, could not be laid out as a handout, and in Safari Print could stop at "Preparing to print…" with nothing printed. Maths served by the site itself also arrives this way.
  • Swift needs a large download, once. The first preview of a course with a runnable Swift program downloads about 1.3 GB and takes a few minutes. Your Mac needs 6 GB free. With less, Plantoir downloads nothing and says the Swift programs are not ready. This happens only if you use runnable Swift.

New

  • Python programs students can run. Add codeRunner: true to a page's settings and mark a code block python run. On the site, students get the program in an editor with Run, Stop and Reset, a box for input when the program reads any, and its output below. Their edits are kept in their own browser. Mark a block python run readonly to show a program they can run and cannot change. On paper a runnable block prints as plain code.
  • Swift programs students can run. Mark a code block swift run on the same kind of page. Students run the program with the input they type; the code stays as you wrote it, and a note under the block says so.
  • Self-check quizzes. A [!quiz] callout holds a multiple choice, select all, short answer or fill-in-the-blank question, with an optional explanation shown after the first Check or Show answer. [!quiz|shuffle] shuffles the choices. Each page keeps a score in the student's own browser ("3 of 5 right on the first try"). A quiz that cannot be checked still shows its question, and Plantoir lists it with the folder's problems. On paper only the questions print.
  • Obsidian can show your diagrams and graphs. The first time you open a course that has them in Obsidian from Plantoir, it asks "Show diagrams and graphs in Obsidian too?" One yes covers every course, and each course gets only the add-ons it uses. If the course is already open in Obsidian, Plantoir asks to reopen Obsidian first. Plantoir never adds them to a course kept for reference or to a course inside a larger vault. Change your answer in Plantoir ▸ Settings ▸ Obsidian.
  • The ready-made ICS3U course uses runnable Python throughout: 83 programs on 41 pages. A course you already created is not changed.
  • Guidance for Claude Code and Codex on writing quizzes.

Changed

  • Your class sites serve what they need to show maths. Maths no longer depends on another website, and it shows offline.
  • An overall curriculum expectation's page lists "When did we do this?": every page that links it or any of its specific expectations. Before, the list was empty.
  • A folder you add later in Course Settings starts with a front page and a _DUPLICATE ME page, like the folders made with the course, so it appears in the site's sidebar.

Fixed

  • When Undo could put back only part of a change because a page had been edited since, the change stayed stuck and later presses did nothing more. Once you have set that page back, pressing Undo again now finishes the job.
  • A printable page opened by a link from a page in another folder is laid out as a handout again when printed. Before, the layout failed, and in Safari nothing printed.

Plantoir 1.4.4

Plantoir 1.4.4 is for the Mac and Windows. Its widest change is to words: "deploy" now always means sending a site to where students read it, and "publish" only means marking a page for students to see. Many buttons and sentences you know now read differently.

New

  • Add units and several classes by typing. "Start a new unit with the next class", "Add three days to Unit 2" and "Add another day to Unit 4" are understood straight away. A request about a new unit or several pages that the assistant cannot place adds nothing, and the assistant names the sentences that work. Before, such a request could add one page to the current unit.
  • Schedule and cancel a deploy by typing. "Schedule a deploy at 6:30 am" and "cancel the scheduled deploy" are understood straight away. "Schedule a deploy" with no time asks for one and never deploys now. Windows has had this since 1.4.3.

Changed

  • "Deploy" and "publish" are kept apart everywhere: in Course Settings (for example "Also deploy to, for redundancy"), the New Course window, the assistant, notifications and the console. The coverage-map switch reads "Include the curriculum coverage map". The starter pages of new courses say "your class website".
  • A course open in Claude Code or Codex is held for that session. Opening a second session on the course is refused, with a message that the course is already being revised. Rename Course, Restore and Add Section… are unavailable until the session ends, and the course's backup is kept.
  • A section that is still being deployed is not deployed again. A deploy from the window, the assistant or the command line is refused while that section's scheduled deploy is still working.
  • A deploy scheduled again while the earlier one is still working waits up to thirty minutes for it, then stands down and says so.

Fixed

  • In new courses, the _DUPLICATE ME template pages had lost the ## and ### marks from their sentence about headings. New courses get the marks; existing courses keep the pages they have.

Plantoir 1.4.3 is for the Mac and Windows. An assistant such as Claude Code or Codex can now change a course while its preview is open, and on Windows the assistant schedules and cancels deploys reliably.

  • "Publish Unit 4, Day 3", typed in that form, is understood straight away.

  • Hiding or publishing a unit, or a class by its date, changes the right page when a class page shares its name with another page.

Plantoir 1.4.0

Plantoir 1.4.0 is for the Mac. Plantoir now updates itself, a new Mac is ready for its first course sooner, and there are new tools for the start of the year, for clubs and for working with an assistant. Windows stayed at 1.1.0; its next release was 1.4.2.

Before you update

  • This is the last release you install by hand. From 1.4.0 on, Plantoir checks for new versions itself and asks before installing one. Version 1.3.1 and earlier cannot do that, so download this one yourself.
  • The download is now about 411 MB. It used to be about 60 MB. Plantoir now carries the helper programs it used to download the first time it ran. A file this much bigger than you remember is still the right file.
  • A deploy you scheduled before updating still happens as you set it. Until it runs it may appear under a slightly different name from new ones. Scheduling that section again replaces it.

New

  • Plantoir updates itself. It checks plantoir.app once a day, and Plantoir ▸ Check for Updates… checks when you ask. The update window shows what changed. Nothing downloads or installs without your click, and nothing installs while Plantoir is building, previewing or deploying.
  • Get Ready for the Start of the Year… hides every class after the first, along with the pages only later classes link to. You see a plan first, and it can be undone.
  • How I Teach. A page in the course folder, never on the website, that Claude Code and Codex read before they work on the course. Course Settings has a How I Teach page row to open or create it.
  • Clubs. Tick "This is a club" in the New Course window for weekly pages ("Week 1"), a front page for the most recent meeting, and no curriculum folder or coverage map unless you add them. The assistant says "meeting" where it would say "class".
  • Two coverage maps. A course with two curriculum folders, such as an Ontario one and a College Board one, gets a coverage map for each. College Board codes such as 1.A and CRD-1.A count as expectations.
  • Notifications for scheduled deploys. A scheduled deploy tells you when it finishes, whether it worked or failed, even with Plantoir closed. Clicking the notification opens that section.
  • Backup sizes. The Backups list shows how much space each backup, each course and all backups take. All Backups deletes several at once.
  • Ask what a class links to. "What does Unit 2, Day 3 link to?" is answered from the page, with hidden pages and links that lead nowhere marked.
  • Ready-made example content for TAS2O.

Changed

  • A new Mac is ready sooner. On a Mac with Apple silicon, Plantoir carries what it used to download on first run, about 857 MB, so the first course does not wait for it.
  • When Plantoir opens for the first time, and the first time it opens after each update, it gets its website builder ready in the background, so the first preview starts sooner. The sidebar says while this is happening.
  • Plantoir opens on the working folder you used last. It refuses a working folder its website builder cannot reach.
  • Folder and file lists in Course Settings and the New Course window are tables with a checkbox beside each name.
  • Every page a class links to, and the front page, carry that class's date for each section. Before, they could show the day the course was made.
  • Hiding a class no longer hides another class it links to.
  • The build warns when a visible class links to pages students cannot see yet.
  • A page whose settings cannot be read is hidden from students and named. Before, it could be shown, or stop the build.
  • Publishing a class follows more kinds of link to the pages it needs: links inside tables, in angle brackets and in Markdown style. A link inside code or an Obsidian comment is never followed.
  • A scheduled deploy goes to the destinations the course has when it runs, which may differ from those it had when you scheduled it. Every deploy uses Course Settings as last saved, and the assistant reads them when it acts. A section says when Course Settings has unsaved changes.
  • Two working folders holding the same course each keep their own scheduled deploy. Before, scheduling one replaced the other's without saying so.
  • "Deploy at 6:30" asks whether you mean morning or evening. For times it cannot place, such as "tonight", the assistant gives you the sentence to type. Before, the small assistant offered to deploy at once.
  • "Publish all of those" asks which pages. "Publish all the classes in Unit 2." publishes the unit.
  • Duplicating a class in a way that moves other classes warns that Undo will not take it back.
  • "Hide from the site's sidebar" and the built site's sidebar now agree, and Save in Course Settings keeps every setting it did not change.
  • Reference copies and imports leave a course's Obsidian add-ons and their settings behind.
  • A course cannot be called "work".
  • Console lines on first run say "your website builder", and a failure says to restart the Mac and try again.

Fixed

  • Adding a section could show pages you had hidden, when a shared page's settings were written in an unusual way.
  • Moving, re-dating or renaming a class could leave part of the old date or title behind.
  • Pages with unusually written settings could be read as hidden, skipped, or broken by a restore.
  • Approving an assistant's change froze the window for up to two minutes while the course was backed up.
  • A deploy to a folder whose name has a colon reported success when nothing was copied.
  • The window, the assistant, a scheduled deploy and an outside assistant could build the same course at once, and one of them showed or deployed a half-written site.
  • Rebuilding the website builder, after an update for example, could stop a build, preview or deploy that was running. It now waits, and does not start while a preview is open.
  • A seventh working folder could not preview or deploy.
  • Two accounts on one Mac could be given the same preview address.
  • A preview's address could be lost during a long first build.
  • On a Mac that could not show previews, a preview built for two minutes before failing. It now stops in about ten seconds.
  • The same working folder spelled with different accents or capitals got a second website builder, and the two cleared each other's work.
  • A scheduled deploy whose build failed named a destination it never reached. It now sends you to Preview.
  • A page that mentions ws://localhost: made deploys to a folder refuse.
  • Setting a course up again lost a marks folder inside another folder, and a course made from example content recorded no marks folders.
  • One unreadable character emptied the problem report.
  • Cancelling a deploy left error text in the console.
  • Editing the How I Teach page marked a section as edited.
  • Skeleton pages said "{subject}" or "a this course course", and the New Course window said "a english skeleton".
  • Four ready-made curriculum pages linked to pages a skeleton course does not have.
