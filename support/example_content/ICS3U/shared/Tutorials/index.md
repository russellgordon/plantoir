Some skills in this course are not concepts and not tasks — they are
*ways of working*: getting Python running, reading an error without
flinching, asking a real person what they actually need. Each tutorial
below teaches one of those once, so every other page can link here
instead of explaining it again.

| [[Keeping a Project Board]] | Knowing what is finished, and what is stuck |

Skim them all early and come back to each when it turns urgent. The
error-message pair earns its keep the first time a program crashes,
which will be soon and is completely normal. And do not leave
[[Interviewing Your Client]] until the culminating project starts —
the habits in it are worth practising on small things first.
