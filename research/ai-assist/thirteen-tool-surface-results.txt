READING THE MISSES HONESTLY
---------------------------

Three of the 4B's four misses are probes for tools the local model can no
longer see — `remember_timetable` and `plan_add_next_class` — and in all
three it falls back to `read_remembered_timetable`, a READ that changes
nothing. They are obsolete probes rather than regressions. Excluding them,
the 4B is 380/390.

The fourth is real: a typo'd "publsh tomorows class ... and the stuff it
links to" chose `publish_pages` with no page named and an open-ended
`onOrAfter`, which would have published the rest of the term. Fixing that in
the tool DESCRIPTION was tried and measured worse (see
description-steer-regression below), so it is refused in code instead.


THE DESCRIPTION-STEER REGRESSION, RECORDED SO IT IS NOT RETRIED
---------------------------------------------------------------

Adding to publish_pages' description: "NOT for one day's class - for a single
day, including tomorrow's class, use publish_class_on instead", and narrowing
the `pages` argument help to require both dates when empty.

Fixed one, broke three. A small model reads a sentence naming another tool as
a recommendation rather than a boundary, and does not reliably work out which
half of the sentence applies to the request in front of it. Reverted to the
byte; the rule went into Swift, where it costs no accuracy because it changes
nothing the model reads.
