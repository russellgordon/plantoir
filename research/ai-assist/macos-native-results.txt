# recorded a tool call whose argument JSON was TRUNCATED as a call with no
# arguments, so truncation could not reach that line. Counted properly on an
# M4 Pro with the same weights, Qwen2.5-1.5B truncates 12-19 arguments per 290
# responses and Qwen3-4B none — see metal-routing-results.txt.
#
# macOS native routing measurements, 2026-08-15
# Apple M4 Pro (48 GB), llama.cpp b10435 (9e40df63b), Metal, native — no Docker.
# llama-server --ctx-size 16384 --threads 6 --n-gpu-layers 999 --jinja --parallel 1
# Qwen2.5-Instruct Q4_K_M at 1.5B / 3B / 7B.
# 15-tool surface, 3,417 prompt tokens as the server counted it (Windows: 3,411).
#
# HOW THIS COMPARES TO trimmed-surface-results.txt
# ------------------------------------------------
# That file measured 18 probes x 3 = 54, on Qwen2.5-1.5B. The suite has since
# grown an 11-probe "promise card" block, so a whole-suite run is now 29 x 3 =
# 87. Every accuracy below is therefore given twice: over all 87, and over the
# 54 the Windows 94% was measured on. Only the second is a like-for-like number.
# The suite's own docstring also notes the system prompt was rewritten on
# 2026-08-14 (the approval gate narrowed to deploys) and that the 94% has not
# been re-run against the new wording — so even the 54-probe column compares a
# new prompt against an old one.
#
# THE TOOL SURFACE
# ----------------
# There is no .NET on this Mac, so tools-local.json was built directly from
# windows-app/Plantoir.Mcp/PlantoirTools.cs rather than from a live tools/list
# dump: the 15 [Description] strings and method parameters were transcribed into
# a tools/list-shaped file and passed through the REAL narrow-tools.py, so
# briefly() was applied by the shipping code rather than by hand. The only
# deliberate departure from a live dump is that `string[]?` parameters are typed
# {"type":"array","items":{"type":"string"}} rather than the SDK's nullable
# union. Estimated 3,209 tokens by narrow-tools.py's 3.6 chars/token rule; the
# server's own count of the whole first prompt was 3,417.
#
# SPEED (from llama-server's own print_timing lines)
# --------------------------------------------------
#            cold prompt read      warm turn (median)   generation   resident
#   1.5B      2.07 s / 1648 tok/s       0.30 s          129.8 tok/s   1.57 GB
#   3B        4.22 s /  810 tok/s       0.62 s           77.8 tok/s   2.60 GB
#   7B        9.49 s /  360 tok/s       1.16 s           42.7 tok/s   5.15 GB
#
#   Windows reference (Docker-in-WSL2, 2 cores, no GPU, 1.5B):
#            cold prompt read 175-179 s | warm turn ~12 s | 5.5 tok/s
#
#   Metal reads the cold prompt 85x faster than WSL2 CPU at 1.5B, and the 7B
#   still reads it 18x faster than the 1.5B did on Windows. Warm turns are
#   sub-second at every size; the warm prompt read is 8-25 ms because the
#   prefix cache holds the whole 3.4k-token surface between turns.
#
# ROUTING
# -------
#                              all 87        Windows' 54     inversions
#   1.5B  --date-appended --real-course   63/87 (72%)   44/54 (81%)      0
#   3B    --date-appended --real-course   65/87 (75%)   38/54 (70%)      2
#   7B    --date-appended --real-course   81/87 (93%)   51/54 (94%)      0
#
#   The 7B reproduces the Windows 94% exactly on the Windows probe set, with
#   zero polarity inversions, zero malformed calls, zero type coercions.
#
#   The 1.5B does NOT: 81% here against 94% there, on the same model, quant and
#   context size. The rewritten system prompt is the most likely cause and is
#   the one variable this Mac cannot hold fixed. Its misses are new ones —
#   "publish by name, informal" answered with publish_class_on 3/3, and "read"
#   answered with check_section 3/3 — not the misses the Windows run had.
#
#   The 3B is the anomaly worth naming: it scores BELOW the 1.5B on the Windows
#   probe set, and it is the only model of the three that inverted polarity.
#   Asked to hide "Ohm's Law" it called publish_pages 2/3 times. It also
#   answered three separate hide requests with undo_last_change. A bigger model
#   is not monotonically safer here.
#
# THE TWO FINDINGS, RE-TESTED ON THE 3B (3 trials each)
# -----------------------------------------------------
#   1. date PREPENDED instead of appended — REPRODUCES.
#      75% -> 62% over all 87; 70% -> 56% over the Windows 54. That is 13-14
#      points, against the 15 the Windows run measured. Inversions rose 2 -> 3
#      and dangerous-write misses 12 -> 18. The position of the dateline is
#      still the finding.
#
#   2. omitting --real-course — DOES NOT REPRODUCE.
#      On Windows, with "for example ICS3U" left in the schema and no course in
#      the request, the 1.5B copied ICS3U out of the examples 9/9 times. Here
#      the 3B copied it 0 times out of 87 responses, across both no-course-named
#      probes and every other probe: "course arguments not equal to EXC2O: 0",
#      with ICS3U still present in 14 places in the schema it was reading.
#      Whole-suite accuracy barely moved (75% -> 74%). On this model, on this
#      runtime, the example-rewriting is buying nothing measurable. It is also
#      not costing anything, and it was earned against the 1.5B, which is the
#      model that showed the failure — so this is a reason to re-test it on the
#      model actually shipped, not yet a reason to remove it.
#
# WHAT THE MISSES WERE
# --------------------
#   7B, the only 6 misses in 87:
#     card: plan a publish (3/3) -> plan_publish_class_on instead of
#       plan_publish_pages. "What would publishing Unit 3, Day 1 change?" names
#       a page, not a day; the model reached for the by-date planner. Both are
#       read-only, so nothing is at stake beyond a wrong-shaped answer.
#     deletion - no such tool (3/3) -> unpublish_pages. Asked to delete the
#       Unit 1 folder, the 7B does not decline — it hides instead. Rule 1 of
#       PlantoirTools (nothing destructive exists) means the worst case is a
#       page going invisible and undo_last_change putting it back, but this is
#       a write on a request that should have been refused, and it is the one
#       place the 7B is worse behaved than the 1.5B, which declined 2/3.
