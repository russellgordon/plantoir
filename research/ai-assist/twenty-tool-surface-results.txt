# ***  AND THE SHIPPING APP IS AFFECTED, RIGHT NOW  ***

#   "Publish Unit 2, Day 3, and everything it links to (Today is ...)"
#   -> 13.0 s, completion_tokens 256, tool_calls [], content begins
#      "Okay, the user wants to publish ... Let me check the available functions."

# That is chain-of-thought filling the whole budget and no tool call — the same
# failure the 39% row in macos-native-10-trial-comparison.txt describes. The
# 97%/100% figures in this file are NOT what the app currently gets. Adding
# "--reasoning", "off" to that argument list (and to the test's assertion) is

# includeLinked gained "Choose deliberately; there is no default."

# --------------------------------------------------------------------------

# ------------------------------------------------------------
#   Qwen3-4B is 130/130 on the new probes — every add_next_class phrasing
#   (including two written not to copy its TEACHERS SAY line, and one worded to
#   bait the dated publish tool: "We meet again on Thursday - add that class"),
#   every read_remembered_timetable phrasing, both remember_timetable ones, and
#   the plan_-only probe. Qwen2.5-1.5B is 121/130.
#
#   The confusion to watch for — add_next_class mistaken for the
#   publish-a-class-on-a-date tool — appeared ONCE in 260 new-probe responses
#   (1.5B, one trial of "the class after this one" -> plan_publish_class_on).
#   That is not a naming problem. The names and TEACHERS SAY lines are working.
#
#   The 1.5B's only real new-tool weakness is "Remind me which days I see this
#   class" — declined 8/10 rather than reaching read_remembered_timetable. The
#   other three timetable phrasings are 10/10, so this is a recall wobble in a
#   small model, not a description gap.
#
# THE ONE THING WORTH FIXING — AND IT IS NOT A NEW TOOL
# -----------------------------------------------------
#   On BOTH current surfaces (B and C), Qwen3-4B answers
#     "Publish tomorrow's class, and everything it links to."   (no course named)
#   and its typo'd twin with:
#     publish_pages {course, section:1, includeLinked:true, onOrAfter:"2026-08-16"}

#   tomorrow onward, not tomorrow's. On surface A the same sentence chose
#   publish_class_on 10/10 with date=2026-08-16.
#
#   The cause is visible in the diff: publish_class_on lost nothing relevant,
#   but it never had an includeLinked knob, and the rewrite made publish_pages
#   the only tool that visibly offers "everything it links to". When the
#   teacher says that phrase without naming a course, the model follows the
#   knob. Note the longer probe that DOES name the course
#   ("...and make sure every page it links to is published") still routes to
#   publish_class_on 10/10, so this is narrow — but it is an over-publish, and
#   over-publishing is the failure class this surface exists to prevent.
#
#   Suggested fix, in publish_class_on's description only: add the phrase to
#   its TEACHERS SAY list — "publish tomorrow's class and everything it links
#   to" — and state plainly that it already publishes linked pages so no
#   includeLinked is needed. No new tool, no schema change.
#
#   Set against that, the rewrite BOUGHT something: "card: plan a publish"
#   ("What would publishing Unit 3, Day 1 change?") went 0/10 -> 10/10 on the
#   4B, taking the promise card to a clean 110/110. That probe was the 4B's
#   only standing miss in the shipped figures.
