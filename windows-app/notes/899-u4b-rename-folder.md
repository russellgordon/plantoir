# #899 U4b on the Mac: what Windows inherits (W8, W4c)

## For PROGRESS

- U4b's first part landed on the mac branch `issue/899-u4b-rename-folder`: U4a review 1's lows L2, L3 and L4 and the U4a sweep's four lows. Rename folder through the door, the order rule for an edit inside a moved folder and the capitalisation-only move are NOT in it yet (U4b's second part).
- Three new `undo.stackCases` rows (L4) are held in `NamedGapLedger.cs` under `Reason899W4c`; W4c runs them. They need two things this replay does not know yet: the call `afterContentGone` (only the newest step's after content of p1 taken out of the list) and the key `keptBesideThePage` (how many staged `-orig` files are beside p1 after the last call). Both are in `undo.stackCasesHow`. On the mac `afterContentGone` also removes the blob's folder in the list's content folder when that leaves it empty, so that with `contentCannotBeStored` (which seals the content folder) the blob truly cannot be written again; a replay whose list writes blobs flat needs nothing more.

## For documentation 12

- **The outgoing bytes of an Undo or a Redo** (W4c): under the lock and before the swap, every page a whole-file op moves FROM THE LIST, whose outgoing bytes the other direction needs and the list lacks, has them written into the list; when the list will not take them they are kept beside the page under the swap's own `-undo-orig` / `-redo-orig` name, unless a kept copy there already holds them. The two `U4a, LOW 4 (a)` rows pin both branches. A door that skips this deletes the only copy at the swap's tidy (the Redo then comes to contentMissing).
- **Kept copies thinned** (W4c): after each move, the step's kept copies beside a page are thinned to one per SHA-256, the newest move's copy kept; an unreadable copy is never removed. `U4a, LOW 4 (b)` (seven moves, two files) pins it.
- **The trail line `undo kept what it replaced`** says the page was put back "from what was kept beside it" ONLY when it was; when the list gave the page's content and only its outgoing bytes were kept, the line says "Undo put back “A.md”, but the list could not keep a copy …" (`activityTrail.mustRecord` → `carries`; the mac's `UndoTrail.keptWhatItReplacedLine(…fromAKeptOriginal:)`). W4c copies the sentence with that switch.
- **A `course_config.json` that is a link** (W8): the mac plans the Save where the link leads (`CourseConfiguration.fileALinkLeadsTo`, following each link of the last component, as many as the system follows) and leaves the link a link. Measured before the fix on the mac: `Data.write(.atomic)` to a link REPLACES the link with a plain file (the pre-U4a Save did that); U4a's door refused it as changed since and the Save could not be made with the switch off. Windows' Save should write through a reparse point the same way.
- **After a Save's make** (W8): the app's copy is the file read back, so another program's change of another member between the plan and the make is in memory too (U4a review 1, LOW 2).
